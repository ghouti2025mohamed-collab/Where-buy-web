# Where Buy Web — واجهة ويب اجتماعية للتسوق

هذه نسخة ويب مستقلة مبنية على مشروع Where Buy المرفوع (Expo / Supabase). تحافظ على مبدأ كتالوج المنتجات والمتاجر الحالي وتضيف طبقة اجتماعية للتواصل والنشر.

## ما الذي يعمل في الواجهة؟

- واجهة عربية RTL ومتجاوبة للكمبيوتر والهاتف.
- عرض المنتجات من `products` وربط المتجر من `companies`.
- البحث والتصنيفات وفتح تفاصيل المنتج والمفضلة.
- إنشاء حساب / تسجيل الدخول عبر Supabase Auth.
- صفحة ملف شخصي تعرض معلومات البائع، رقم الهاتف العام، منتجات متجره ومنشوراته.
- منشورات نصية أو صورة أو فيديو، مع إرفاق منتج موجود من كتالوج المنتجات.
- قصص صور وفيديو تنتهي بعد 24 ساعة.
- محادثات مباشرة ورسائل نصية ومرفقات صور وفيديو.
- مكالمات صوتية ومرئية عبر WebRTC مع تبادل إشارات الاتصال من خلال Supabase.

## التشغيل

1. فك ضغط المشروع وافتح المجلد في بيئة Node.js.
2. انسخ `.env.example` إلى `.env.local`.
3. ضع عنوان Supabase ومفتاح Publishable / anon الخاص بمشروعك في `.env.local`:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```

4. من Supabase SQL Editor نفّذ الملف كاملًا:
   `supabase/migrations/20261101_wherebuy_social_web.sql`
5. ثبّت وشغّل:

```bash
npm install
npm run dev
```

ثم افتح عنوان Vite الظاهر في الطرفية.

## توافق قاعدة البيانات

تعتمد الواجهة على الجداول الحالية في مشروع الهاتف:
- `products`: الأعمدة `id, name, description, price, image_url, stock, company_id, created_at`.
- `companies`: الأعمدة `id, owner_id, name, address, phone, description`.
- `profiles`: الأعمدة الحالية للحساب (`id, full_name, phone, role` على الأقل).
- `favorites`: `user_id, product_id` للمفضلة.

الترحيل ينشئ جداول اجتماعية مستقلة: `public_profiles`, `social_posts`, `stories`, `conversations`, `messages`, `call_signals`، وينشئ bucket باسم `social-media` للمنشورات والقصص وbucket خاصًا `chat-media` لمرفقات المحادثات.

## ملاحظات أمان وخصوصية

- ضع مفتاح Publishable / anon فقط في واجهة الويب. لا تستخدم `service_role` في المتصفح مطلقًا.
- جدول `public_profiles` مخصص للمعلومات التي يختار المستخدم نشرها على صفحته. حقل الهاتف يبقى فارغًا للمستخدمين الحاليين إلى أن يضيفه صاحبه؛ أما هاتف المتجر فيؤخذ من `companies.phone` كما في تطبيق الهاتف.
- سياسات RLS تمنع المستخدم من قراءة محادثات أو مرفقات محادثات لا ينتمي إليها.
- وسائط المنشورات والقصص عامة، ومرفقات الدردشة خاصة وتُعرض برابط مؤقت.
- المكالمات تستخدم WebRTC وSTUN تجريبيًا. يلزم نشر الموقع عبر HTTPS والسماح بالكاميرا والميكروفون. لا تتضمن الحزمة TURN server؛ لذلك قد لا تنجح المكالمات على بعض الشبكات أو خلف NAT صارم. للإنتاج، أضف TURN موثوقًا.
- رفع الملفات محدود بـ 100MB في إعدادات bucket المبدئية؛ يمكن خفض الحد حسب سياسة المنصة وتكلفة التخزين.
- يلزم تفعيل تأكيد البريد وسياسات كلمات المرور المناسبة من Supabase Auth قبل الإطلاق العام.

## حدود النسخة الحالية

- هذه نسخة أولية عملية للويب وليست اعتماد نشر نهائيًا. لم يتم ربطها فعليًا بمشروع Supabase الحي أو اختبار RLS على حسابات متعددة.
- البحث الذكي CLIP الموجود في تطبيق الهاتف لم يُنقل إلى المتصفح؛ البحث النصي والكتالوج الحاليان يعملان هنا، ويمكن دمج محرك البحث الذكي لاحقًا كخدمة ويب مستقلة.
- صفحة المنتج تعرض بيانات المنتج ورقم المتجر والمراسلة؛ الدفع والطلبات والشحن غير مضافة في هذه المرحلة.
- المفضلة تتزامن مع جدول `favorites` الموجود إذا كانت سياساته وأعمدته مهيأة بشكل صحيح.
